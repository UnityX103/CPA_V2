# 休息期间键鼠活动辅助在场检测

番茄钟设置新增「允许检测键盘和鼠标活动」，默认关闭，点击应用后生效。该授权独立于摄像头，保存在本机 `presence-preferences.json` 的 schema v5；旧版本数据默认不授权。主窗口拥有采样状态，设置窗口通过现有 bridge 同步配置和可用状态。

## 判定及生命周期

- 只在休息计时运行、因在场自动暂停、或自然进入等待开始的休息阶段采样。专注、完成、手动暂停、关闭授权和卸载监视器后停止定时器。
- 每 5 秒按需查询一次，最多一个未完成请求。不安装全局输入事件钩子，不复用持续运行的按键计数器，不读取、保存或上传按键、文本、鼠标位置。
- 最近 30 秒内有输入即为在场。单独启用键鼠检测时，连续无输入满 30 秒允许继续由在场检测暂停的休息。这是输入活动推断，不能证明人确实离开。
- 摄像头和输入各自保留证据；任一来源确认在场即在场。已启用的来源都确认无在场证据后才允许继续休息。摄像头仍使用原有离席防抖，输入轮询不累计摄像头漏检次数。
- 摄像头错误、待授权、过期或输入查询失败时，该来源为未知；另一来源的明确在场仍有效，但未知不会触发自动继续休息。输入证据 10 秒未更新失效；摄像头证据在采样间隔加 12 秒超时后失效。
- 手动暂停不被自动恢复。手动继续休息沿用原来的人工覆盖规则，直到一次确认离场后再重新允许在场暂停。
- 撤销授权、切换休息轮次、退出休息或释放监视器后丢弃迟到结果。关闭输入授权不重启摄像头。
- 继续通过通用 Pomodoro 在场暂停事件触发 `break.present`，蟑螂功能包无需新增协议或重新下载。

## 原生接口

平台中立命令 `sample_input_activity` 仅返回空闲毫秒数；调用失败显式返回错误。macOS 使用 [CGEventSource 的 elapsed-event 查询](https://developer.apple.com/documentation/coregraphics/cgeventsource)，Windows 使用 [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo) 与 GetTickCount 的环绕减法。Windows 信息仅覆盖当前登录会话。两者查询系统已有的空闲状态，无事件钩子和常驻采样线程，无需额外的系统输入监听授权；应用内授权仍必须开启。

## 验证

覆盖单独输入检测、双来源合并、摄像头漏检防抖隔离、失败和过期证据、人工控制、生命周期及迟到结果、v5 保存迁移和设置窗口同步。macOS 原生 API 本机 1000 次查询全部成功，合计约 21 ms（不含 Tauri IPC；单机一次测量）。Windows 模块通过 x86_64-pc-windows-msvc 独立编译检查；完整应用交叉编译受缺少 Windows C 工具链影响，当前虚拟机不可用，尚未完成 Windows 实机验证。
